# Quarter-Car Suspension Modeling and Simulation

## Project Objective

The objective of this project is to build, test, and tune a quarter-car suspension model using MATLAB, Simulink, and Simscape Multibody. The model represents one corner of a vehicle using:

- A sprung mass representing the vehicle body
- An unsprung mass representing the wheel assembly
- A suspension spring and damper
- Tire stiffness and damping
- A moving road input

The suspension is evaluated on five road profiles: a speed bump, pothole, rough road, washboard road, and two consecutive bumps. Performance is measured using:

- **Ride comfort:** RMS sprung mass vertical acceleration
- **Suspension packaging:** Maximum absolute suspension travel
- **Road holding:** Maximum absolute tire deflection

A road case passes when all three requirements are satisfied:

| Requirement | Limit |
|---|---:|
| RMS sprung mass acceleration | `<= 2.0 m/s^2` |
| Maximum suspension travel | `<= 0.08 m` |
| Maximum tire deflection | `<= 0.03 m` |

The project also performs a parameter sweep over suspension spring stiffness (`Ks`) and damping (`Cs`) and identifies the combination with the lowest worst case score across all road cases. A separate robustness test increases the sprung mass by 25% and reruns the road suite.

## Required Software 

The project files were created in **MATLAB R2026a**. The following MathWorks products are required:

- MATLAB
- Simulink
- Simscape
- Simscape Multibody

Using MATLAB R2026a or newer is recommended. An older MATLAB release may be unable to open files saved in a newer release.

## Project Files

| File | Description |
|---|---|
| `QuarterCarSuspension_StudentProject.mlx` | Final Live Script containing the project explanation, workflow, and results sections. |
| `quarterCarModel.slx` | Simulink and Simscape Multibody quarter-car model. |
| `setupQuarterCar.m` | Defines the baseline vehicle, suspension, tire, and road input parameters. |
| `roadSuite.m` | Generates the five road profile inputs as MATLAB `timeseries` objects. |
| `scoreSuspension.m` | Extracts simulation signals and calculates comfort, suspension travel, tire deflection, and combined score metrics. |
| `runAllTests.m` | Runs the baseline suspension on all road cases, checks the requirements, and saves a summary table and plot. |
| `tuneSuspension.m` | Sweeps candidate `Ks` and `Cs` values and ranks each design by its worst-case score. |
| `robustnessTest.m` | Increases the baseline sprung mass by 25%, reruns all road cases, and reports the pass rate. |
| `quarterCarModel.slxc` | Generated Simulink file. This file is optional and can be regenerated by MATLAB. |
| `results/summaryTable.mat` | Generated by `runAllTests.m`; contains the baseline results table. |
| `results/summaryPlot.png` | Generated by `runAllTests.m`; shows the score for each road case. |

## How to Run the Project

### 1. Prepare the project folder

Place all `.m`, `.slx`, and `.mlx` files in the same folder. Open MATLAB and set that folder as the **Current Folder**.

For repeatable random-road results, set the random-number seed before running the tests:

```matlab
clear;
clc;
close all;
rng(0);
```

### 2. Open and inspect the model

```matlab
open_system('quarterCarModel');
```

The model expects the parameters `Ms`, `Mu`, `Ks`, `Cs`, `Kt`, `Ct`, and `roadInput` in the MATLAB base workspace.

### 3. Run one road case manually

Edit the `roadCase` value in `setupQuarterCar.m`, or run the following commands:

```matlab
setupQuarterCar;
roadCase = 'speedBump';
roadInput = roadSuite(roadCase);

simIn = Simulink.SimulationInput('quarterCarModel');
simOut = sim(simIn);
results = scoreSuspension(simOut, roadCase)
```

Valid road-case names are:

```matlab
'speedBump'
'pothole'
'roughRoad'
'washboard'
'twoBumps'
```

### 4. Run the complete baseline test suite

```matlab
rng(0);
summaryTable = runAllTests();
```

This command:

1. Loads the baseline suspension parameters.
2. Runs all five road cases.
3. Calculates the performance metrics.
4. Reports pass or fail for each case.
5. Creates the `results` folder if it does not exist.
6. Saves `results/summaryTable.mat` and `results/summaryPlot.png`.

### 5. Tune the suspension

```matlab
rng(0);
tuneResults = tuneSuspension();
```

The tuning script evaluates these values:

```matlab
Ks = [12000, 14000, 16000, 18000, 20000];   % N/m
Cs = [1000, 1500, 2000, 2500, 3000];        % N*s/m
```

This produces 25 candidate designs. Each design is tested on all five road cases. The script sorts the designs by `worstScore` and displays the design with the lowest worst-case score.

The recommended design is the first row of the sorted results. Record its `Ks`, `Cs`, `worstScore`, and `allPass` values in the final Live Script and use the results table or plots to justify the selection.

### 6. Run the robustness test

```matlab
rng(0);
robustResults = robustnessTest();
```

This test increases the sprung mass from `300 kg` to `375 kg`, reruns all five road cases, and prints the percentage of cases that pass.

**Important:** The current `robustnessTest.m` reloads the baseline values from `setupQuarterCar.m`. It therefore tests the baseline `Ks = 12000 N/m` and `Cs = 1000 N*s/m`, not the best values returned by `tuneSuspension.m`. To validate the tuned design, update `Ks` and `Cs` inside `robustnessTest.m`, pass them into the function, or update the baseline values in `setupQuarterCar.m` before running the robustness test.

### 7. Run the final Live Script

Open `QuarterCarSuspension_StudentProject.mlx` in MATLAB Live Editor and select **Run All**. Confirm that all tables, figures, design recommendations, and interpretation sections are updated before exporting the final document.

## How to Reproduce the Results

Use the following order in a fresh MATLAB session:

```matlab
clear;
clc;
close all;
rng(0);

summaryTable = runAllTests();
tuneResults = tuneSuspension();
robustResults = robustnessTest();
```

Then open and run:

```matlab
open('QuarterCarSuspension_StudentProject.mlx');
```

To reproduce the same results successfully:

- Keep all project files in one folder.
- Do not rename the model or logged signals.
- Keep the model name as `quarterCarModel`.
- Keep the logged signal names as `sprungAccel`, `suspTravel`, and `tireDeflection`.
- Use the same parameter values and road-case names.
- Run `rng(0)` before testing because the rough-road profile contains random values.
- Confirm that the model simulation stop time covers the full five-second road input.

## Reproducibility and Interpretation Notes

### Random rough-road input

`roadSuite.m` generates the rough-road profile using random values. Without a fixed random-number seed, the rough-road results may change between runs. Running `rng(0)` makes the overall run repeatable.

For the fairest parameter comparison, every `Ks` and `Cs` combination should be tested using the same saved rough-road signal. The current tuning script generates a new rough-road realization during the sweep, so different designs may receive slightly different random inputs even though the complete sweep is repeatable after setting the seed.

### Combined score

The combined score is calculated as:

```matlab
score = comfortRMS + packagingMax + roadHoldingMax;
```

Because this score directly adds values with different units and scales, it should be treated as a project-specific ranking metric rather than a physical quantity. The individual limits and pass/fail results should also be considered when selecting the final suspension design.

### Current robustness scope

The implemented robustness study evaluates a 25% payload increase. It does not currently perform a ±10% `Ks` and `Cs` tolerance study or a 20-trial Monte Carlo analysis.
